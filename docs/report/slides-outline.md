## 2. รายละเอียดสไลด์แต่ละหน้า (Slide-by-Slide Details)

### สไลด์ที่ 1: หน้าปก (Title Slide)
* **หัวข้อ:** ระบบรับรองแหล่งที่มาผ้าไหมทอมือบุรีรัมย์ด้วยเทคโนโลยีบล็อกเชน (Buriram Hand-woven Silk Traceability on Local Consortium Blockchain)
* **ผู้จัดทำ:** รายชื่อสมาชิกในกลุ่ม พร้อมบทบาท (BA, Frontend, Backend, Blockchain/QA, PM)
* **อาจารย์ที่ปรึกษา / รายวิชา:** ภาควิชาวิศวกรรมคอมพิวเตอร์ / เทคโนโลยีสารสนเทศ

### สไลด์ที่ 2–3: ปัญหาผ้าไหมบุรีรัมย์และระบบเดิม (Problem Statement - 3 นาที)
* **สถิติจริงในพื้นที่:** กลุ่มทอผ้าไหม OTOP บุรีรัมย์กว่า 46 กลุ่ม, สหกรณ์บ้านหัวสะพาน/กลุ่มตุ้มทองกว่า 700 ครัวเรือน
* **วิกฤตไหมเทียมและการปลอมแปลง:** ข้อมูลคดีทรัพย์สินทางปัญญากว่า 1,140 ล้านบาท และการแข่งขันกับผ้าพิมพ์ลายใยสังเคราะห์ราคาถูก
* **จุดอ่อนของระบบเดิม:** บันทึกกระดาษ / ไลน์กลุ่ม / ใบรับรองกระดาษที่ปลอมแปลงได้ง่ายและตรวจสอบย้อนหลังไม่ได้

### สไลด์ที่ 4–5: ทำไมต้องบล็อกเชน & ทำไม Consortium PoA (Why Blockchain & PoA - 4 นาที)
* **SQL Counterfactual:** ถ้าใช้ MySQL/PostgreSQL ธรรมดา ใครเป็นเจ้าของฐานข้อมูล? เจ้าของแก้ประวัติย้อนหลังได้หรือไม่? ทำไมหลายองค์กรไม่ยอมให้อีกฝ่ายถือข้อมูลฝ่ายเดียว?
* **Consortium Model:** กระจายสิทธิ์ระหว่าง 3 องค์กร (สหกรณ์ + หน่วยงานตรวจรับรอง + เครือข่ายร้านค้า)
* **Proof of Authority (PoA):** เหตุผลที่ไม่ใช้ PoW (ไม่มีการขุด/เป็นมิตรต่อสิ่งแวดล้อม), ไม่ใช้ Crypto/Token, อาศัยชื่อเสียงและความรับผิดชอบของ 3 หน่วยงาน

### สไลด์ที่ 6–7: สถาปัตยกรรมระบบและโครงสร้างข้อมูล (Architecture & Block Structure - 4 นาที)
* **System Architecture Diagram:** การแบ่งเลเยอร์ Nuxt 4 + PostgreSQL + Append-only Ledger Simulator
* **On-chain vs Off-chain Breakdown:** ข้อมูลลับ/PII อยู่ Off-chain, ข้อมูลรับรอง/Cryptographic Hash อยู่ On-chain (สอดคล้องกับ PDPA)
* **Block Structure & Cryptographic Chain:** ฟิลด์ในบล็อก (Index, Timestamp, Data Hash, Nonce รอบ, Previous Hash, Validator ID, Ed25519 Signature)

### สไลด์ที่ 8–11: การสาธิตระบบสด (Live System Demo - 5 นาที)
* **Scenario 1 (Weaver):** ช่างทอลงทะเบียนผ้าไหมผืนใหม่ แนบภาพถ่ายกระบวนการทอ และกดส่งคำขอรับรอง
* **Scenario 2 (Cooperative Officer):** เจ้าหน้าที่เปิดคิวตรวจ ตรวจสอบข้อมูล และกดอนุมัติ -> ระบบลงนามและสร้างบล็อกใหม่ทันที
* **Scenario 3 (Store Transfer):** สหกรณ์ส่งมอบผ้าให้ร้านค้า -> ร้านค้ายืนยันรับมอบ (Custody Chain อัปเดตลงบล็อกเชน)
* **Scenario 4 (Public Verification & Explorer):** ผู้บริโภคสแกน QR Code เพื่อดูใบรับรอง และเปิดดูหน้า Blockchain Explorer เพื่อตรวจสอบ Chain Integrity

### สไลด์ที่ 12–13: ความเป็นไปได้ ข้อจำกัด และจริยธรรม (Limitations & Ethics - 2 นาที)
* **Cost-Benefit 8 มิติ:** เปรียบเทียบต้นทุนเซิร์ฟเวอร์และการดำเนินงาน
* **ข้อจำกัดทางเทคนิค:** ระบบเป็น Local Simulation เพื่อการศึกษา, ปัญหา Oracle/GIGO, ปัญหาการคัดลอก QR Code
* **PDPA & จริยธรรม:** การคุ้มครองข้อมูลช่างทอสูงอายุ และสิทธิในการขอลบข้อมูล

### สไลด์ที่ 14: สรุปและแผนพัฒนาในอนาคต (Conclusion & Future Work)
* สรุปคุณค่าของระบบ: เพิ่มมูลค่าผ้าไหมทอมือบุรีรัมย์ สร้างความโปร่งใสที่ตรวจสอบได้จริง
* ก้าวต่อไป: Pilot ร่วมกับสหกรณ์จริง, แยกโหนดบนระบบคลาวด์หลายองค์กร และการฝัง NFC Tag

## 3. คู่มือเตรียมตอบคำถามกรรมการ (Q&A Defense Cheat Sheet)

| คำถามยอดฮิตจากอาจารย์ | แนวทางการตอบที่ถูกต้องและสร้างความประทับใจ |
|---|---|
| **1. "ทำไมไม่ใช้ Relational Database (SQL) ธรรมดาพร้อม Audit Log ทำไมต้องบล็อกเชนให้ยุ่งยาก?"** | **ตอบ:** "หากในความเป็นจริงทุกฝ่าย (ช่างทอ สหกรณ์ ร้านค้า ผู้บริโภค) ไว้วางใจสหกรณ์เพียงองค์กรเดียวอย่างสมบูรณ์แบบ 100% ฐานข้อมูล SQL ธรรมดาก็เพียงพอและประหยัดที่สุดครับ แต่ในความเป็นจริง ห่วงโซ่อุปทานมีหลายองค์กรที่มีผลประโยชน์ต่างกัน หากสหกรณ์เป็นเจ้าของ Database เจ้าเดียว ผู้ดูแลระบบ (DBA) ก็สามารถแก้ไขประวัติย้อนหลังหรือลบประวัติการทุจริตได้โดยไม่มีใครรู้ บล็อกเชนแบบ Consortium จึงเข้ามาแก้ **'Trust Problem ระหว่างองค์กร'** โดยใช้ Cryptographic Hash Chain และการลงนามร่วมหลายฝ่าย ทำให้ไม่มีใครสามารถแก้ไขข้อมูลในอดีตได้เพียงลำพังครับ" |
| **2. "ระบบนี้เป็นบล็อกเชนจริงหรือไม่ หรือเป็นแค่การจำลอง (Simulation)?"** | **ตอบ:** "ระบบนี้เป็น **Local Consortium Blockchain Simulation** ที่ถูกพัฒนาขึ้นเพื่อการศึกษาเชิงสถาปัตยกรรมครับ เราจำลองอัลกอริทึม SHA-256 Hash Chain, การหมุนเวียน Validator แบบ Round-Robin ของ PoA และการลงนาม Ed25519 จริงทุกบล็อก โดยทำงานบนตาราง Append-only ใน PostgreSQL ที่มี DB Trigger ป้องกันการ Update/Delete ครับ แม้โหนดจะยังรันอยู่ในเครื่องเดียว แต่โครงสร้างข้อมูล ตรรกะฉันทามติ และการตรวจสอบความสมบูรณ์เป็นตรรกะเดียวกับ Permissioned Blockchain จริงครับ" |
| **3. "ถ้ามีคนถ่ายรูป QR Code จากผ้าไหมแท้ ไปพิมพ์แปะบนผ้าไหมปลอม บล็อกเชนช่วยอะไรได้?"** | **ตอบ:** "บล็อกเชนไม่สามารถป้องกันการคัดลอก QR Code ในเชิงกายภาพได้ครับ (ปัญหา Physical-Digital Link / Oracle Problem) แต่ระบบของเราแก้ปัญหานี้ด้วย 2 กลยุทธ์คือ: (1) หน้าเว็บตรวจสอบจะแสดงภาพถ่ายลวดลายเฉพาะและขนาดของผ้าจริง เพื่อให้ผู้ซื้อเปรียบเทียบกับผ้าในมือ และ (2) ระบบมีไทม์ไลน์การส่งมอบ (Custody Chain) ทำให้ผู้ซื้อตรวจสอบได้ว่าร้านค้าที่ตนกำลังซื้ออยู่นั้น ได้รับมอบผ้าผืนนี้มาอย่างถูกต้องในระบบหรือไม่ครับ ในอนาคตเราวางแผนพัฒนาไปใช้ชิป NFC เข้ารหัสที่ฝังในเนื้อผ้าครับ" |
| **4. "มีหลักฐานหรือข้อมูลตัวเลขจริงไหมว่าผ้าไหมมีการปลอมแปลงและสร้างความเสียหายเท่าใด?"** | **ตอบ:** "มีข้อมูลอ้างอิงชัดเจนครับ จากสถิติกรมทรัพย์สินทางปัญญาปี 2568 มีคดีจับกุมสินค้าละเมิดทรัพย์สินทางปัญญากว่า 1,132 คดี มูลค่าเสียหายกว่า 1,140 ล้านบาท (เพิ่มขึ้น 63.89%) และรายงานจาก ISAN Insight ระบุว่าในภาคอีสานมีการนำใยสังเคราะห์ 100% มาแอบอ้างขายเป็นไหมแท้ ส่งผลให้ยอดขายผ้าไหมในแหล่งผลิตสำคัญลดลงถึง 26% ในปี 2566 ครับ" |
| **5. "การบันทึกข้อมูลแบบลบไม่ได้บนบล็อกเชน ขัดกับสิทธิในการขอลบข้อมูล (Right to be Forgotten) ของ PDPA หรือไม่?"** | **ตอบ:** "ไม่ขัดครับ เพราะระบบของเราออกแบบสถาปัตยกรรมแยกแบบ **On-Chain / Off-Chain** โดยบนบล็อกเชนเราบันทึกเฉพาะ Cryptographic Hash (SHA-256) และรหัสแบบนามแฝง (UUID) ซึ่งไม่สามารถย้อนกลับเป็นข้อมูลส่วนบุคคลได้ ส่วนชื่อ-สกุลจริงและข้อมูล PII ทั้งหมดจะถูกเก็บไว้ใน PostgreSQL ภายนอก เมื่อช่างทอใช้สิทธิขอลบข้อมูล เราสามารถลบ PII ในฐานข้อมูลออกได้ทันที ทำให้ Hash บนบล็อกเชนกลายเป็นแฮชที่ไม่สามารถเชื่อมโยงถึงตัวบุคคลได้อีกต่อไปครับ" |
