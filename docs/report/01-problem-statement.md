# 1. Problem Statement — ปัญหาและความจำเป็นของระบบ

## 1.1 ปัญหาด้วยข้อมูลจริงบุรีรัมย์

### 1.1.1 ความสำคัญของผ้าไหมบุรีรัมย์

จังหวัดบุรีรัมย์เป็นแหล่งผลิตผ้าไหมทอมือที่มีความสำคัญของประเทศไทย โดยมีประวัติการทอผ้าไหมสืบทอดกันมายาวนานกว่า 200 ปี ในพื้นที่อำเภอพุทไธสง (กรมหม่อนไหม, 2568) จากการสำรวจของกรมวิทยาศาสตร์บริการ พบว่ามีกลุ่มผู้ประกอบการ OTOP ประเภทผ้าและเครื่องแต่งกายในจังหวัดบุรีรัมย์จำนวน 46 กลุ่ม ครอบคลุมผู้ประกอบการกว่า 2,000 ราย (กรมวิทยาศาสตร์บริการ, 2562)

กลุ่มทอผ้าไหมที่สำคัญในจังหวัดบุรีรัมย์ ได้แก่:
- **กลุ่มทอผ้าไหมบ้านหัวสะพาน** ตำบลบ้านยาง อำเภอพุทไธสง — จัดตั้งสหกรณ์เมื่อวันที่ 23 ธันวาคม 2553 มีสมาชิกกว่า 700 คน ในพื้นที่ 17 หมู่บ้าน (Go Ahead News, 2566)
- **กลุ่มตุ้มทอง** ตำบลนาโพธิ์ อำเภอนาโพธิ์ — จัดตั้งเมื่อปี 2540 เริ่มต้นสมาชิก 15 คน ปัจจุบันมีสมาชิกกว่า 700 คน ในพื้นที่ 17 หมู่บ้าน (Go Ahead News, 2566)
- **สหกรณ์การเกษตรทอผ้าไหมบ้านคู จำกัด** — มีสมาชิกสามัญรวม 148 คน สมาชิกสามัญหญิง 140 คน (Thailand Company Directory, 2566)
- **กลุ่มทอผ้าไหมบ้านหนองม่วง** ตำบลหนองม่วง อำเภอคูเมือง — เป็นหนึ่งใน 5 ชุมชนเป้าหมายของโครงการพัฒนาขีดความสามารถแบบ Cluster (จีวัฒนา & ภัทรศรีจิรากุล, 2562)

จากการวิจัยของจีวัฒนาและภัทรศรีจิรากุล (2015) พบว่าการพัฒนาระบบฐานข้อมูลผ้าไหมทอมือของกลุ่มวิสาหกิจชุมชนจังหวัดบุรีรัมย์เป็นความจำเป็นเพื่อการบริหารจัดการข้อมูลและการตลาดอย่างเป็นระบบ

### 1.1.2 ปัญหาการปลอมแปลงและไหมเทียม

จากข้อมูลของกรมทรัพย์สินทางปัญญา ในช่วง 11 เดือนแรกของปี 2568 (มกราคม - พฤศจิกายน) มีการจับกุมสินค้าละเมิดทรัพย์สินทางปัญญาทั่วประเทศ 1,132 คดี ยึดของกลาง 3,344,841 ชิ้น รวมมูลค่าความเสียหายกว่า 1,140 ล้านบาท (Thansettakij, 2568) ซึ่งเพิ่มขึ้นจากปี 2567 ที่มีมูลค่าความเสียหาย 700 ล้านบาท เพิ่มขึ้น 63.89%

สำหรับผ้าไหมโดยเฉพาะ จากการสำรวจของ ISAN Insight (2568) พบว่ามีปัญหาการใช้ใยสังเคราะห์ผสมไหม หรือใยสังเคราะห์ 100% แต่กลับแอบอ้างว่าเป็น 'ไหมแท้' หรือร้านที่ขายทั้งไหมแท้และไหมเทียม แต่กลับให้ข้อมูลบิดเบือนหรือสร้างความเข้าใจผิด ทำให้เกิดความเสียหายต่อผู้บริโภคและผู้ผลิตผ้าไหมแท้

ในพื้นที่อำเภอปักธงชัย จังหวัดนครราชสีมา ซึ่งเป็นแหล่งผลิตผ้าไหมที่สำคัญที่สุดของประเทศไทย พบว่ายอดขายผ้าไหมลดลงถึง 26% ในปี 2566 เมื่อเทียบกับปี 2565 สะท้อนถึงผลกระทบจากการแข่งขันกับสินค้าราคาถูกและไหมเทียม (ISAN Insight, 2568)

### 1.1.3 ปัญหาความต่อเนื่องของภูมิปัญญา

จากการวิจัยของ The Isaan Record (2569) พบว่าช่างทอผ้าในภาคอีสานกำลังเผชิญกับปัญหา:
- คนรุ่นใหม่ย้ายไปทำงานในเมืองเพราะมีรายได้ดีกว่า
- ชุมชนทอผ้าไหมเหลือผู้สูงอายุเป็นแรงงานหลัก
- ภูมิปัญญาการทอผ้าเสี่ยงที่จะไม่ถูกส่งต่อไปยังคนรุ่นต่อไป
- ลวดลายผ้าของคนในชุมชนถูกลอกแบบไปขายในราคาถูก ผ้าพิมพ์ลายจากโรงงานมีราคาถูกกว่าผ้าไหมทอมือเกือบ 10 เท่า

สำหรับจังหวัดบุรีรัมย์ จากการสำรวจของมูลวันดีและคณะ (2015) พบว่ากลุ่มทอผ้าไหมบ้านโนนศิลา มีความจำเป็นต้องมีการศึกษาระบบบัญชีชุมชนโดยการมีส่วนร่วมเพื่อการบริหารจัดการที่มีประสิทธิภาพ

## 1.2 ระบบเดิมและช่องว่าง

### 1.2.1 วิธีทำงานปัจจุบัน

ปัจจุบัน ระบบรับรองแหล่งที่มาของผ้าไหมบุรีรัมย์ทำงานโดยใช้วิธีดังนี้:

1. **กระดานบันทึกและใบรับรองกระดาษ** — ช่างทอบันทึกข้อมูลผ้าไหมในกระดานบันทึกของตัวเองหรือสหกรณ์ โดยใช้กระดานบันทึกกระดาษหรือไฟล์ Excel ซึ่งมีความเสี่ยงต่อการสูญหายหรือการแก้ไข

2. **ใบรับรองกระดาษ** — สหกรณ์ออกใบรับรองรับรองแหล่งที่มาของผ้าไหมในรูปแบบกระดาษ ซึ่งอาจถูกปลอมแปลงหรือสูญหายได้ง่าย และยากต่อผู้บริโภคในการตรวจสอบความถูกต้อง

3. **การสื่อสารผ่านไลน์กลุ่ม** — การสื่อสารระหว่างช่างทอ สหกรณ์ และร้านค้าส่วนใหญ่ทำผ่านไลน์กลุ่ม ซึ่งข้อมูลอาจไม่เป็นระบบและยากต่อการติดตามประวัติ

4. **การตรวจสอบโดยผู้บริโภค** — ผู้บริโภคต้องพึ่งพาใบรับรองกระดาษไปให้สหกรณ์ตรวจสอบ หรือติดต่อกับช่างทอโดยตรง ซึ่งใช้เวลาและไม่สะดวก

### 1.2.2 ช่องว่างของระบบเดิม

1. **ความเสี่ยงต่อการแก้ไขประวัติ** — ข้อมูลที่บันทึกในกระดานบันทึกกระดาษหรือไฟล์ Excel สามารถถูกแก้ไข ลบ หรือทำลายได้โดยไม่มีการตรวจสอบ ทำให้ไม่สามารถรับรองความถูกต้องของข้อมูลย้อนหลังได้

2. **ความยากในการตรวจสอบ** — ผู้บริโภคไม่มีวิธีที่สะดวกและเชื่อถือได้ในการตรวจสอบความถูกต้องของใบรับรอง โดยเฉพาะเมื่อซื้อผ่านช่องทางออนไลน์

3. **ขาดความโปร่งใส** — ข้อมูลเกี่ยวกับการรับรองและประวัติของผ้าไหมไม่เปิดเผยอย่างโปร่งใส ทำให้ผู้บริโภคไม่มั่นใจในความถูกต้องของสินค้า

4. **การแบ่งปันข้อมูลที่ไม่มีประสิทธิภาพ** — การสื่อสารระหว่างองค์กรต่าง ๆ (ช่างทอ สหกรณ์ ร้านค้า) ทำผ่านช่องทางที่ไม่เป็นระบบ ทำให้ข้อมูลอาจไม่ตรงกันหรือล่าช้า

5. **ความเสี่ยงต่อการปลอมแปลงใบรับรอง** — ใบรับรองกระดาษสามารถถูกปลอมแปลงได้ง่าย และยากต่อการตรวจสอบความถูกต้อง

## 1.3 SQL Counterfactual: ทำไมระบบฐานข้อมูลรวมศูนย์ไม่เพียงพอ

หากใช้ระบบฐานข้อมูลรวมศูนย์ (Centralized Database) เช่น MySQL หรือ PostgreSQL โดยมีองค์กรเดียวเป็นเจ้าของและควบคุมข้อมูลทั้งหมด จะเกิดปัญหาดังนี้:

### 1.3.1 ใครเป็นเจ้าของฐานข้อมูล

หากใช้ระบบฐานข้อมูลรวมศูนย์ จะต้องมีองค์กรหนึ่งที่เป็นเจ้าของ Database Server และมีสิทธิ์เข้าถึงข้อมูลทั้งหมด ในกรณีของผ้าไหมบุรีรัมย์ องค์กรที่เป็นไปได้คือสหกรณ์ผ้าไหม ซึ่งเป็นองค์กรที่ทำหน้าที่รับรองและออกใบรับรอง

### 1.3.2 ใครสามารถแก้ประวัติย้อนหลังได้

ในระบบฐานข้อมูลรวมศูนย์ เจ้าของ Database (สหกรณ์) หรือผู้ดูแลระบบ (Database Administrator) มีสิทธิ์เต็มในการแก้ไข ลบ หรือทำลายข้อมูลได้ แม้ว่าจะมี Audit Log ก็ตาม แต่ Audit Log เองก็ถูกเก็บไว้ใน Database เดียวกัน ซึ่งสามารถถูกแก้ไขได้โดยผู้ที่มีสิทธิ์สูงกว่า

### 1.3.3 ทำไมหลายองค์กรไม่ยอมให้อีกฝ่ายถือข้อมูล

ในความเป็นจริง หากทุกฝ่าย (ช่างทอ สหกรณ์ ร้านค้า) เชื่อถือสหกรณ์เดียวกันอย่างสมบูรณ์ว่าจะไม่แก้ไขข้อมูล ระบบฐานข้อมูลรวมศูนย์พร้อม Audit Log อาจเพียงพอได้ อย่างไรก็ตาม ในทางปฏิบัติ มีปัจจัยดังนี้ที่ทำให้หลายองค์กรไม่ยอมให้อีกฝ่ายถือข้อมูลทั้งหมด:

1. **ความกังวลเรื่องความโปร่งใส** — แม้ว่าสหกรณ์จะไม่แก้ไขข้อมูล แต่หากไม่มีกลไกที่เปิดเผยให้เห็นได้ชัดเจนว่าข้อมูลไม่ถูกแก้ไข องค์กรอื่นอาจไม่มั่นใจ

2. **ความเสี่ยงต่อการเปลี่ยนแปลงผู้บริหาร** — หากในอนาคตมีการเปลี่ยนแปลงผู้บริหารสหกรณ์ หรือมีความขัดแย้งภายใน องค์กรอื่นอาจไม่ปลอดใจให้ข้อมูลสำคัญอยู่ในการควบคุมของสหกรณ์

3. **ความจำเป็นในการตรวจสอบข้ามองค์กร** — ร้านค้าและผู้บริโภคอาจต้องการตรวจสอบได้ด้วยตัวเองว่าข้อมูลถูกต้อง โดยไม่ต้องพึ่งไปถามสหกรณ์

4. **การกระจายอำนาจ** — หากข้อมูลทั้งหมดอยู่ใน Database ของสหกรณ์ จะทำให้สหกรณ์มีอำนาจมากเกินไปในการควบคุมข้อมูล

อย่างไรก็ตาม หากทุกฝ่ายเชื่อถือสหกรณ์เดียวกันอย่างสมบูรณ์และมีกลไก Audit Log ที่เข้มแข็ง ระบบ SQL อาจเพียงพอได้ แต่ในความเป็นจริงมักจะไม่มีใครยอมรับให้มีองค์กรเดียวควบคุมข้อมูลทั้งหมด

## 1.4 Trust Problem: ความจำเป็นต้องใช้บันทึกร่วมกัน

จากการวิเคราะห์ พบว่ามี 2–3 องค์กรที่จำเป็นต้องใช้บันทึกร่วมกันและไม่มีใครควรแก้ประวัติทั้งหมดได้ลำพัง:

1. **สหกรณ์ผ้าไหมบุรีรัมย์** — เป็นผู้รับรองและออกใบรับรอง ต้องมีบันทึกว่าได้รับรองผ้าไหมชิ้นใด จากช่างทอคนใด และอนุมัติเมื่อใด

2. **หน่วยงานตรวจรับรองท้องถิ่น** — ในระบบจริงอาจมีหน่วยงานราชการที่ทำหน้าที่ตรวจรับรองเพิ่มเติม ซึ่งต้องมีบันทึกว่าได้ตรวจและรับรองชิ้นใด

3. **ร้านค้าหรือเครือข่ายร้านค้า** — เป็นผู้ที่รับผ้าไหมไปขาย ต้องมีบันทึกว่าได้รับผ้าไหมชิ้นใด จากใคร และเมื่อใด

ปัญหาคือ หากข้อมูลทั้งหมดถูกเก็บไว้ใน Database ของสหกรณ์ สหกรณ์จะสามารถแก้ไขข้อมูลได้โดยลำพัง ซึ่งอาจส่งผลกระทบต่อความเชื่อถือของร้านค้าและผู้บริโภค

ดังนั้น จำเป็นต้องมีระบบที่ทำให้ทุกองค์กรสามารถ:
- บันทึกข้อมูลร่วมกัน
- ตรวจสอบได้ว่าข้อมูลไม่ถูกแก้ไข
- ไม่มีองค์กรใดควรแก้ประวัติทั้งหมดได้ลำพัง

## 1.5 ขอบเขตการรับรอง

สำคัญต้องชัดเจนว่า **ใบรับรองดิจิทัลที่ระบบนี้ออกให้ยืนยันเฉพาะ**:

- **ผู้ทอ** — ยืนยันว่าผ้าไหมนี้ทอโดยช่างทอคนใด
- **แหล่งผลิต** — ยืนยันว่าผ้าไหมนี้ผลิตที่ไหน ในพื้นที่ใด
- **ผู้ตรวจรับ** — ยืนยันว่าผ้าไหมนี้ผ่านการตรวจรับรองโดยใคร
- **วันที่** — ยืนยันว่าผ้าไหมนี้ผลิตและได้รับรองเมื่อใด

**ใบรับรองไม่ได้ยืนยัน**:
- คุณภาพแท้ทั้งหมดของผ้าไหม (เช่น ความทนทาน ความละเอียดของการทอ)
- ว่าผ้าไหมนี้คือผ้าไหมที่ดีที่สุด
- ว่าผ้าไหมนี้ไม่มีข้อบกพนกับคุณภาพอื่น ๆ

ขอบเขตการรับรองนี้สำคัญเพื่อไม่ทำให้ผู้บริโภคเข้าใจผิดว่าใบรับรองรับประกันคุณภาพทั้งหมด
