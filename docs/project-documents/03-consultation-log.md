## 1. การให้คำปรึกษารอบที่ 1: สัปดาห์ที่ 14 (Architecture & Design Review)

* **วัน/เวลา:** วันพุธที่ 12 สัปดาห์ที่ 14 (เวลา 13:30 – 13:45 น. / 15 นาที)
* **ผู้เข้าร่วม:** สมาชิกในกลุ่มครบทั้ง 5 คน และอาจารย์ผู้สอน

### 1.1 ประเด็นที่นำเสนอต่ออาจารย์
1. นำเสนอ Problem Statement ข้อมูลสถิติผ้าไหมบุรีรัมย์จริง และเหตุผลที่เปรียบเทียบกับ SQL Counterfactual
2. โครงสร้างสถาปัตยกรรมระบบ Consortium Blockchain ร่วมกับ Proof of Authority (PoA)
3. การออกแบบ Block Structure, การแยกระหว่าง On-Chain และ Off-Chain Data เพื่อให้สอดคล้องกับ PDPA
4. แผนการพัฒนา Implementation เสริมด้วยเว็บแอปพลิเคชัน Nuxt 4 เพื่อสาธิตการทำงาน

### 1.2 ข้อเสนอแนะและ Feedback จากอาจารย์
1. **เรื่อง Consensus และ Nonce:** อาจารย์ย้ำว่าเมื่อเลือก PoA ค่า `Nonce` ในโครงสร้างบล็อกจะต้องอธิบายตามบริบทของ PoA (เช่น เป็นตัวนับ Sequence Counter ของ Validator เพื่อกัน Replay Attack) ห้ามนำคำอธิบายการขุดเหมือง (Mining Nonce) ของ PoW มาใส่ปะปน
2. **เรื่อง Smart Contract:** ต้องเขียนเป็น **Pseudo-code เท่านั้น** ห้ามเขียนเป็น Solidity code ในรายงาน เนื่องจากวิชานี้ต้องการวัดความเข้าใจตรรกะเชิงสถาปัตยกรรม
3. **เรื่องความเสี่ยงของบล็อกเชน:** ห้ามวิเคราะห์ 51% Attack เพราะเป็นความเสี่ยงของ PoW ให้วิเคราะห์ความเสี่ยงการสมรู้ร่วมคิดของ Validator (Collusion) หรือ Key Compromise แทน
4. **ความสมดุลของการใช้ SQL vs Blockchain:** ให้ยอมรับอย่างตรงไปตรงมาว่าถ้าทุกฝ่ายเชื่อถือสหกรณ์องค์กรเดียว ระบบ SQL ธรรมดาก็เพียงพอ แต่ให้เน้นย้ำจุดขายเรื่องการแก้ปัญหา Trust Gap ข้ามองค์กร
