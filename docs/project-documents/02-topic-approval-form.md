## 2. การวิเคราะห์ปัญหาและความจำเป็น (Problem Statement & Justification — ภาคผนวก B ข้อ 1)

### 2.1 สภาพปัญหาและบริบทเชิงพื้นที่ของจังหวัดบุรีรัมย์
จังหวัดบุรีรัมย์มีกลุ่มวิสาหกิจชุมชนและช่างทอผ้าไหม OTOP มากกว่า 46 กลุ่ม มีสมาชิกกว่า 2,000 ราย โดยเฉพาะในพื้นที่อำเภอพุทไธสง (สหกรณ์บ้านหัวสะพาน) และอำเภอนาโพธิ์ (กลุ่มตุ้มทอง) ซึ่งสร้างสรรค์ผ้าไหมมัดหมี่ทอมือที่มีมูลค่าสูง อย่างไรก็ตาม ปัจจุบันประสบปัญหาสำคัญ:
1. **การแข่งขันกับผ้าไหมเทียมและผ้าพิมพ์ลายราคาถูก:** มีการนำเข้าเส้นใยสังเคราะห์ 100% หรือไหมผสมมาแอบอ้างขายเป็นไหมแท้ ส่งผลให้ยอดขายผ้าไหมแท้ในภูมิภาคอีสานลดลงถึง 26% (ISAN Insight, 2568) และสร้างความเสียหายต่อชื่อเสียงหัตถกรรมพื้นเมือง
2. **จุดอ่อนของระบบรับรองเดิม:** ใช้ใบรับรองกระดาษและสมุดบันทึก ซึ่งสามารถถูกปลอมแปลง ทำลาย หรือสับเปลี่ยนกับผ้าผืนอื่นได้ง่าย และยากต่อผู้บริโภคในการตรวจสอบย้อนกลับความจริงทางออนไลน์

### 2.2 เหตุผลที่ระบบฐานข้อมูลรวมศูนย์ (SQL Database) ไม่ตอบโจทย์เพียงพอ
หากใช้ฐานข้อมูล MySQL หรือ PostgreSQL รวมศูนย์เพียงองค์กรเดียว:
* **ปัญหาความเป็นเจ้าของและการแก้ไขประวัติย้อนหลัง (Trust Problem):** ผู้ดูแลระบบ (DBA) หรือองค์กรที่ถือฐานข้อมูล (เช่น สหกรณ์รายใดรายหนึ่ง) มีสิทธิ์แก้ไข ลบ หรือปลอมแปลงประวัติการรับรองย้อนหลังได้โดยที่ร้านค้าและผู้บริโภคไม่สามารถตรวจสอบได้
* **การขาดความร่วมมือระหว่างหลายองค์กร:** ในห่วงโซ่คุณค่ามีทั้งช่างทอ สหกรณ์ หน่วยงานตรวจรับรอง และเครือข่ายร้านค้า ซึ่งต่างฝ่ายต่างไม่ยินยอมให้อีกฝ่ายหนึ่งถือสิทธิ์ควบคุมฐานข้อมูลทั้งหมดแต่เพียงผู้เดียว

## 3. สถาปัตยกรรมระบบที่นำเสนอ (Proposed Architecture — ภาคผนวก B ข้อ 2)

### 3.1 รูปแบบบล็อกเชนและกลไกฉันทามติที่เลือก (Blockchain Type & Consensus)
* **Blockchain Type:** **Consortium Blockchain (บล็อกเชนแบบพันธมิตร)** — กำหนดสิทธิ์ให้เฉพาะกลุ่มองค์กรที่ทราบตัวตน (สหกรณ์, หน่วยงานตรวจรับรอง, เครือข่ายร้านค้า) มีสิทธิ์เขียนและลงนามบล็อก ขณะที่เปิดให้ผู้บริโภคและสาธารณชนอ่านข้อมูลเพื่อตรวจสอบได้อย่างเสรี
* **Consensus Mechanism:** **Proof of Authority (PoA)** — ใช้การหมุนเวียนโหนดผู้ตรวจสอบ (3 Validator Roles) แบบ Round-Robin ลงนามด้วย Ed25519 ไม่ใช้การขุด (PoW) ไม่ต้องมีเหรียญคริปโทเคอร์เรนซี ประหยัดพลังงาน และเหมาะสมกับบริบทวิสาหกิจชุมชน

### 3.2 ธุรกรรมหลักของระบบ (2–3 Key Transactions)
1. **การออกใบรับรองดิจิทัล (`ISSUE_CERTIFICATE`):** เมื่อช่างทอยื่นคำขอและสหกรณ์ตรวจรับรองผ่าน ระบบจะคำนวณ Cryptographic SHA-256 Hash ของข้อมูลผ้าและรูปภาพ จากนั้น Validator ประจำรอบจะลงนามสร้างบล็อกและออก QR Code
2. **การส่งมอบการครอบครอง (`TRANSFER_ACCEPTED`):** เมื่อผ้าไหมถูกส่งมอบต่อให้ร้านค้าตัวแทน ร้านค้าจะกดยืนยันการรับมอบ ระบบจะบันทึกประวัติการเปลี่ยนมือลงบล็อกเชน ทำให้ตรวจสอบ Custody Chain ได้
3. **การตรวจสอบย้อนกลับสาธารณะ (`VERIFY_PROVENANCE`):** ผู้บริโภคสแกน QR Code บนผืนผ้า ระบบจะทำการ Query ข้อมูลพร้อมคำนวณ Hash Chain Integrity ยืนยันว่าประวัติไม่เคยถูกดัดแปลง
